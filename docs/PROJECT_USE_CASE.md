# 项目用例图

在“工作区视图 → 项目 → 项目用例图”进入，也可从项目概览和用户故事地图进入。每个项目只有一张专属用例图，不作为 Story 的设计资产，也不与资产中心的普通 UML 图混用。

## 一一对应

故事地图的顶层目标是唯一的业务数据来源。图中的每个用例由目标 ID 派生，名称直接读取目标名称；持久化数据仅记录参与者、目标对应节点的位置与连线，不重复保存一套用例名称。

- 在地图中新增、改名或删除目标，图中的对应用例自动变化。
- 在用例图点击“新增用例 / 目标”，会同时创建一个顶层目标。选择用例后点击“编辑名称”，可修改同一目标的名称和领域。
- 相同名称的不同目标仍按 ID 分别对应，不按文字猜测关系。已有 Epic、Story、Task、Subtask 继续关联原来的目标。
- 目标用例不能转换为参与者，也不能从图中单独解绑。参与者可独立新增、改名和删除。

## 编辑与查看

复用 UML 画布，可以拖动节点、从边缘锚点连接节点、修改关系类型与标签、删除连线、缩放和平移。“整理布局”重新排列现有节点，保留参与者名称和连线。“定位到用户地图”会打开并突出显示对应目标。

支持导出全图 PNG 和 PlantUML 源码。导出文件不会自动成为 Story 的设计资产。

## 删除规则

删除用例即删除对应目标。确认窗口展示 Epic、Story、Task 和 Subtask 的影响数量，确认后复用现有目标子树删除逻辑，并清理专属图的相关连线和位置。取消不修改目标或连线；含已关闭 Sprint 的 Story 时阻止删除。

## 保存与迁移

schema 20 在项目数据中增加 projectUseCase。旧项目首次加载时根据现有目标建立对应布局，默认添加可编辑的 PO 参与者和关联；不会改动原目标、需求或 Story 资产。新增目标会自动出现在专属图，参与者关系可按项目实际情况连接。自定义位置、参与者和连线随本地保存及 JSON 导入导出保留；已删除目标的遗留布局和连线会清理，非法图数据导入失败时保留当前项目。
