# Sprint 燃尽图

进入“工作区视图 → Sprint 管理”，在详情统计卡片下方查看。顶部或左侧切换 Sprint 后自动更新。

## 工时口径

复用工作量分析的剩余工时计算：预计总工时 × (1 − 进度 / 100)，已完成项计 0。有子任务的 Task 只汇总 Subtask；没有子任务时统计 Task。本图展示工程执行进度，与 Release 按 Story 验收计算的交付进度分别使用各自口径。

顶部展示当前范围的总工时、剩余工时、工时加权完成比例和预计完成日期，并单独标出初始工时基线。新增、移除范围以及修改估算都会反映在实际曲线上。

## 三条曲线

- Ideal：启动时冻结的初始总工时，按 Sprint 起止日期之间的自然日线性下降到 0。规划中的 Sprint 显示当前范围的理想预览。
- Actual：真实记录的每日剩余工时。每天使用最后一次观测值，可持平、上升或下降。悬浮或键盘聚焦日期可查看三类工时；缺少快照时显示“未记录”。
- Forecast：用首次和最近一次快照之间的平均每日净燃尽速度预测，从最近实际点延伸到预计归零日。至少需要两个不同日期；速度不为正时明确显示无法预测，不伪造完成日期。预测日期超过 Sprint 结束日期时提示可能延期。

## 历史保存

schema 19 在项目数据中增加 sprintBurndowns，随本地保存、JSON 导入导出一起持久化。业务操作在同一状态事务中记录快照，覆盖进度、状态、估算、Task / Subtask 增删及 Story 的 Sprint 归属变化。过去日期不改写；关闭 Sprint 时先冻结关闭前的实际工时，再结转未完成 Story，避免移出范围导致错误清零。

日期统一使用 Asia/Shanghai。应用恢复后、前台运行期间每分钟及窗口重新获得焦点时补记当前日期的真实观测；应用未运行期间不生成任何历史数据，空缺日期不补值，曲线连线只连接已观测点。对升级前已进行的 Sprint，从首次真实观测日建立基线并说明记录起点；已关闭且没有快照的 Sprint 显示历史缺失提示。

## 验证

单元测试覆盖父子去重、工时和进度变化、日内更新、历史保留、空缺日期、范围上升、停滞与延期预测、关闭前冻结、JSON 迁移及非法历史拒绝、上海日期边界。浏览器使用独立数据目录验证三条曲线、悬浮和键盘提示、切换 Sprint、任务更新联动以及刷新后的历史恢复；视觉检查用的历史样例只写入测试数据目录。
