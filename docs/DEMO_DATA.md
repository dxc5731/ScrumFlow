# 完整示例项目

默认初始化与“重置演示数据”使用当前数据结构生成可编辑的完整项目；已有项目不会在启动时被覆盖。初始化和重置共用固定排期：2026-10-10 至 2026-10-31。Story、Task 和 Subtask 按工作先后及并行关系错开，Epic 汇总子项日期；已有项目恢复时不会自动覆盖用户调整。

## 场景

- 5 个目标、11 个 Epic、29 个 Story，目标下 1–3 个 Epic，每个 Epic 下 1–4 个 Story；另含一个尚未归类的调研候选。
- 46 个工程任务、9 个子任务、5 名成员、6 份资产和 4 条风险记录。
- 3 个 Release：已发布的 V1.0、执行中的 V1.1、规划中的 V1.2。
- 4 个 Sprint：已关闭并复盘、正在执行、同版本后续迭代、下一版本迭代。
- 工程项包含前端、后端、数据库、测试、设计和运维，以及待办、进行中、待审核、完成、普通依赖阻塞、严重手动阻塞。部分任务拆为子任务，工时只统计执行叶节点。
- Story 包含已验收、待验收、退回返工、逾期、候选、草稿、就绪、未分配 Release 及已定版本但未排 Sprint 的情况。退回沿用现有业务规则：执行状态为进行中，验收日志保留退回原因。
- 验收条件、提交说明、内联交付记录、讨论、风险登记及版本调整原因互相关联。风险覆盖开放、处理中、已解决三个状态。
- 独立项目用例图与五个目标一一对应，同时保留 Story 级用例、时序、类图和活动图资产。内联 Markdown 指南与成果记录可以直接预览、下载及随 JSON 迁移。

## 燃尽历史

Sprint 1 提供已结束的每日观测样例；Sprint 2 提供连续快照，包含持平、范围增加与下降。预测按新排期重新计算，当前默认预测可以在截止日前完成，更新进度后会正常判断是否延期。最后一个快照与当前执行叶节点工时完全一致；规划 Sprint 不预设执行历史。这些快照保留调整排期前的观测日期，不因计划改到 10 月而重新计算或平移。所有快照均为明确标注的模拟演示数据，不是由当前进度反推的真实历史，也不冒充本项目实际执行记录。后续更新任务使用正常快照机制。

## 实现与验证

`src/data/currentDemo.ts` 维护当前场景，复用原默认数据的 UML 样例；`createBaseDemoProjectState` 只为已有动作回归保留固定夹具，`createDemoProjectState` 才是用户初始化入口。新增回归覆盖当前场景的完整引用、版本归属、用例同步、工时去重、导入导出、发布门禁与历史保护。

本次替换前的项目原文件备份在 `output/demo-initialization/project-state-before-initialization.json`。初始化后可用“导出项目 JSON”保存当前项目；再次重置将替换现有项目，不会清理旧附件文件。
