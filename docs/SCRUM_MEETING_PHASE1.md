# Scrum 会议主持第一阶段

在项目概览、Sprint、Story 详情的原有会议入口选择类型，再点击“开始会议”。历史会议不强制迁移，原有对话、纪要、Proposal 和项目数据继续沿用。

| 类型 | 默认时长 | 议程 |
| --- | --- | --- |
| 每日站会 | 15 分钟 | 昨日进展 → 今日计划 → 当前阻塞 |
| Sprint Planning | 90 分钟 | Sprint Goal → Story 选择 → 任务拆解与容量确认 |
| Sprint Review | 60 分钟 | 成果展示 → 验收反馈 → 后续调整 |
| Sprint Retrospective | 45 分钟 | 回顾事实 → 分析问题 → 制定改进措施 |

## 课堂录屏顺序

1. 运行 `npm run dev`，访问 `http://localhost:8443/`。使用支持中文播报的 Edge 或 Chrome，先在实际录屏设备上试听。
2. 点击“发起项目会议”，选择“每日站会”和真实 Sprint，开启“主持人语音播报”“演示模式 · 计时 ×30”，点击“开始会议”。展示项目主持欢迎、真实关联任务和顶部时钟。
3. 点击“下一议程”进入今日计划，再进入当前阻塞。成员仍可自由发言，模板不会阻止讨论。
4. 从开始计时约 26 秒出现黄色提醒，约 30 秒出现红色超时提醒，项目主持主动发送文字并尝试播报。录制提醒时先停止成员麦克风，主持播报在录音期间暂停以避免回声。
5. 选择“延长 5 分钟”或“延长 10 分钟”，展示新的剩余时间；演示模式下分别增加约 10 秒、20 秒实际等待时间。
6. 可切换语音开关，或选择发言成员后使用原有“语音发言”展示实时字幕和逐句保存；切换成员会取消上一位成员的录音。
7. 点击“结束会议”，查看主持人的议程完成提示和原有纪要/待确认行动，再点击“确认结束会议”（有待处理项时为“保留待处理并结束会议”）。自然语言摘要复用原有模型通道，可能需要等待；项目计划变更仍需人工审核。
8. 刷新后打开最近会议，展示讨论、纪要和结束状态。重新打开不会重播历史主持消息。

## 计时和数据含义

- `meetingType` 与 `facilitation` 都是可选字段。旧会议没有这些字段时继续使用原会议室，不补写虚构的历史计时。
- `startedAt` 与结束时间用于计算实际用时；页面刷新、后台切换后重新从时间戳计算，不依赖计时器累加。超时不自动结束。
- `plannedMinutes` 是包含手动延期的最终预算；正常模式保存 `actualDurationMs` 和 `actualOvertimeMs`。
- 演示模式明确显示“演示模式 ×30”，`actualDurationMs` 仍是实际墙钟用时；`actualOvertimeMs` 为 `null`，演示时间另存 `demoElapsedMs`、`demoOvertimeMs`，不可作为真实会议或成员发言时长。
- 本阶段没有成员发言时长统计，不从语音句数或演示时钟推算贡献。

## 复用和事件入口

`meetingFacilitation.ts` 统一配置四类会议的名称、时长、议程和引导语。议程直接使用现有 `session.topics`，通过 `agendaKey` 标记；自由讨论产生的原有议题与议程共存。

`projectStore.dispatchMeetingHostEvent` 是统一主动事件入口，消息以 `project_orchestrator` 身份保存到原会议记录，不触发问答编排、递归 AI 回复或 Proposal 执行。开场、议程、提醒、延期和结束前提示使用模板；需要项目事实时读取真实 Sprint/Story/任务/负责人。现有模型解释通道也接收会议类型和当前议程。

提醒按预算时间去重，延期产生新的期限；议程引导按当前阶段去重，两个不同成员补充后可以提示收束，不定时催促。结束确认按已完成议程和待处理行动数去重，返回讨论后有进度变化会更新提示。后续纠偏或风险提醒可扩展这一入口。

`useMeetingHostSpeech` 使用浏览器原生 `speechSynthesis`，优先选择 `zh-CN`，新事件打断旧播报。静音、结束、关闭或切换会议、页面离开时清理；录音期间的新主持消息只保留文字，不在停止录音后补播。无法使用语音时保持文字会议可用。
