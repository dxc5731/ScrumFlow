# ScrumFlow 完整站会录屏方案

## 录制准备

建议 1440×900、浏览器缩放 100%，关闭主持语音即可完成文字版答辩。先使用正式项目数据的隔离副本；演练审批会真实写回该副本，不能将演练结果当成正式项目已执行。不要为演示修改任务、工时或风险。重复录制可从原始副本重新开始，避免系统正确去重后无法再次生成同一建议。

本轮验收副本使用 `PROJECT_DATA_DIRECTORY=output/scrum-phase3/data`、端口 18445。该目录已包含真实演练记录，适合直接查看洞察和导出样例；如需重录审批过程，请另外复制正式数据到新的演练目录，不覆盖现有证据。普通启动方式仍为 `npm run dev`。隔离目录中的旧资产若没有复制 blob 文件，可能无法预览；本轮新生成报告的文件随该目录保留。

当前真实背景：Sprint 2 的计划日期为 2026-09-14 至 2026-09-27，已过计划期。`FE-025-1`「甘特依赖连接线渲染」负责人李娜，状态 blocked；上游 `DATA-024`「定义 Story 与 Task 数据模型」负责人张伟；已登记 `risk-fe025`「依赖连线实现受前置数据阻塞」。录制当天先核对这些对象，数据变化时采用当时事实，不照念旧状态。

## 完整操作与台词（约 5～7 分钟）

| 步骤 | 操作 / 真实输入 | 成功时应出现的画面 |
| --- | --- | --- |
| 1 开始 | 项目概览 → 发起项目会议 → 每日站会 → Sprint 2 → 关闭语音播报 → 开始会议。主链路建议普通计时。 | 主持人自动开场，顶部显示 Sprint、三阶段议程和真实倒计时。 |
| 2 正常汇报 | 发言成员选张伟，输入「昨天我继续核对接口联调和任务进展，今天先确认当前排期。」 | 消息以张伟身份保存；没有因为正常技术/排期讨论产生纠偏。等主持检查结束后继续。 |
| 3 持续偏题 | 连续提交「我们周末要不要组织一次聚餐？」和「我觉得可以去学校附近吃火锅，大家有什么推荐吗？」 | 静默片刻后，主持人温和提醒回到当前议程，显示返回当前议程、继续讨论、判断有误。模型响应时间有波动，不连续补发固定句子催触发。 |
| 4 接受纠偏 | 点击「返回当前议程」。 | 原提醒变为已返回当前议程；此反馈稍后进入报告时间线。 |
| 5 今日计划 | 点击下一议程；成员切换李娜，输入「今天先核对甘特依赖连线与前置接口的交接条件。」 | 主持人自动引导今日计划；新增消息归属李娜，成果图将体现两位实际参与成员。 |
| 6 当前阻塞 | 再点下一议程。 | 主持人从真实 Sprint 任务中选 1～2 项优先关注的阻塞；如 Sprint 已过计划期，如实提醒。具体任务以当前数据为准。 |
| 7 新阻塞线索 | 保持李娜身份，输入「我负责的 #FE-025-1 暂时做不了，因为前置的数据结构还没确定，可能影响后面的测试。」 | 主持人引用「甘特依赖连接线渲染」，提出核对上游条件与恢复时间；不自动修改数据。 |
| 8 风险分析 | 对这条提醒点击「查看依赖影响」。 | 原风险与依赖 Agent 给出真实前置 DATA-024、负责人和后续影响；假设延期单独标 What-if。 |
| 9 形成建议 | 点击「加入待确认行动」。 | 右侧出现更新现有风险的 Proposal，初始待确认。强调：没有新增重复风险，正式项目计划此时仍未改变。 |
| 10 审批与执行 | 逐项查看建议 → 点击采纳 → 点击「重新校验最终计划」 → 阅读最终校验 → 点击「确认应用」。 | 采纳后仍待执行；最终确认后才显示实际执行。查看风险应对措施中的新增跟进文字，保留对应 ChangeHistory。 |
| 11 结束 | 可点击完成议程；点击结束会议，查看结束前纪要，再点击确认结束会议。 | 主持人保存带真实数字的成果汇报；会议状态结束，自动进入洞察。模型摘要只在结束时整理，等待摘要完成后录下一段。 |
| 12 量化成果 | 停留洞察概览与三图，向下滚动。 | 真实用时、参与人数、消息条数、议程推进、AI 干预、行动状态；已采纳和执行成功明确分开。数字以本场记录为准，不预设固定结果。 |
| 13 证据与审计 | 主持时间线点话题纠偏/发言依据；回到纪要洞察，查看关键行动，展开实际变更。 | 定位到真实发言；反馈和任务引用可查；审计显示应对措施变更前后、时间和 ID。点击原始 Proposal 可回右侧审核记录。 |
| 14 复盘 | 查看会议执行复盘、下一步和最多三项推荐。 | 模型文字与事实统计分开；不把风险跟进写成阻塞已解除，不虚构负责人或日期。 |
| 15 导出 | 点击导出会议报告，随后在报告材料卡预览；可加入材料包并下载。 | 实际下载 Word；报告包含摘要、三图对应数据表、主持事件、Proposal 和 ChangeHistory。HTML 可打印保存 PDF。 |
| 16 恢复 | 刷新，项目概览 → 查看最近会议 → 会议纪要 → 查看会议洞察。 | 同一快照、摘要、审批状态和资产恢复，无新纠偏、重复结束汇报或自动模型连发。 |

「查看待处理行动」回到原右侧决策区；如果本场没有待审建议，显示已完成的审核记录即可，不制造未完成事项。会议已结束后的界面保留原只读约束；如需继续审批已有建议，使用原全局待确认建议入口，报告只跟踪本场明确归属的审计。

## 可选的 30 秒计时镜头

另开一场每日站会，勾选「演示模式 ×30」。约 26 秒出现黄色两分钟提醒，约 30 秒红色超时。可演示延期 5 分钟后再结束。洞察必须同时显示实际几十秒与加速后的演示计时，旁白说明「这里仅加速议程时钟，不伪造真实耗时」。此镜头无需重复审批风险；第二场应当复用已存在建议，不能把上一场行动算成本场新成果。

## 建议保留的 8 个关键镜头

1. 自动开场 + 紧凑 Scrum 顶栏：展示主动主持。
2. 两句闲聊 → 一次语义纠偏 → 用户返回议程：展示理解、温和干预和可推翻机制。
3. 进入阻塞议程 → 真实任务引用与已过期 Sprint：展示事实读取。
4. 李娜补充 FE-025-1 → 风险 Agent 的 DATA-024 依赖分析：展示上下文闭环。
5. 待确认 → 采纳 → 最终校验 → 确认应用：展示人工控制与真实写回。
6. 结束后的五项概览 + 三图：展示有依据的成果。
7. 时间线定位原发言 + 关键行动变更审计：展示可追溯性。
8. 执行复盘 + Word 预览/下载：展示可交付的正式报告。

答辩可用一句话解释：系统把成员讨论转为有依据的建议，经人工确认才写回项目，再用消息、主持事件和审批审计复盘；这些事实帮助管理判断，不是团队生产力、个人贡献或 AI 智能度的评分。
