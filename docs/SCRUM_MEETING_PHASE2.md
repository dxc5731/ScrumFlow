# Scrum 会议第二阶段：主动主持与行动闭环

## 本轮实现

- 沿用 `MeetingRoom` 三栏和 `session.topics` 议程。顶部合并标题、会议类型、Sprint、主持状态、计时与主操作；第二行显示水平议程。历史、成员头像、延期、彩排与技术详情收进图标/更多菜单。黄色、红色状态只占计时区域，完整提醒保留在聊天记录。
- `dispatchMeetingHostEvent` 扩展 `topic_deviation`、`sprint_blocker`、`blocker_followup`，持久化来源发言、任务/风险引用、用户反馈和分析记录。新增事件沿用项目主持身份与原语音播报开关，不进入普通问答编排，不触发递归回复。
- 已提交的真实成员发言在安静 2.4 秒后合并检查。纠偏至少需要两条各不少于 10 字、合计不少于 32 字的发言；近期窗口最多 8 条，重点判断最新两条。技术障碍、排期和真实任务名称优先放行，疑似偏离再经现有模型通道复核。结构化结果必须引用真实发言且置信度不低于 0.85。模型不可用时，仅对连续两条明确会外交流保守降级；未知内容不提醒。模型话术不直接采用，避免夹带无依据的项目事实。
- 智能提醒之间至少间隔 8 秒；纠偏冷却 90 秒，同类讨论 5 分钟内不重复提醒。“继续讨论”静默 2 分钟，“判断有误”静默 5 分钟并记住该类话题；“返回当前议程”只记录反馈，不锁定发言或强制切换议程。普通流程引导让位于阻塞与时间提醒。
- 语音转写仍逐句保存，录音中不做话题复核。普通 Scrum 成员陈述直接记录；显式 `@助手`、数字成员邀请和项目分析请求继续沿用原多 Agent 通道。观察器排除主持消息、已处理问答与显式助手请求。
- 进入站会“当前阻塞”时复用事件检测器的依赖/逾期证据和已有阻塞状态，优先关注 1～2 项真实任务，明确说明已过期的 Sprint 计划。成员新增阻塞线索与正式状态分开；只有唯一任务 ID 或完整任务名才自动引用，否则要求选定真实 Sprint 任务。
- 点击“查看依赖影响”调用既有风险与依赖 Agent，再用既有依赖图接口解释上下游；不新增依赖计算、容量计算或风险评分，不宣称确定延期。量化推演仍是独立的 What-if。
- 点击“加入待确认行动”使用标准 `origin: meeting` Proposal。有关联风险时补充既有风险的跟进措施，无可靠风险记录时只建议创建任务讨论。相同建议复用已有会议/事件 Proposal，不重复创建风险。审批前不修改正式任务或风险；采纳、最终复核、确认应用仍走原执行器、前置条件检查和 ChangeHistory。
- 切换会议、议程、录音状态、结束和离开页面会取消在途观察。检测游标在模型请求前持久化，刷新只处理新发言，不重新解释历史或补播历史提醒。尚未完成的复核被取消时不追补，优先避免重复和过时干预。

计时加速只影响议程时钟。冷却、真实会议时长和项目事实均使用真实时间。

## 可直接录屏的站会剧本

建议 1440×900、PO 身份。主场景选择普通计时，避免讨论尚未结束时演示时钟已多次超时；最后另录 30 倍速片段。演练写回请使用明确的项目副本。正式项目的任务状态、依赖和已有风险不应为了演示而改造。

当前数据可使用 Sprint 2 的 `FE-025-1`「甘特依赖连接线渲染」。项目登记负责人为李娜，上游是 `DATA-024`「定义 Story 与 Task 数据模型」，已有风险为「依赖连线实现受前置数据阻塞」。录制前核对这些记录是否仍存在；如已更新，替换为当前真实的阻塞任务，不强行沿用旧结论。

| 步骤 | 用户操作/输入 | 预期可见行为 |
| --- | --- | --- |
| 1 | 项目概览 → 发起项目会议 → 每日站会 → 关联 Sprint 2 → 开始会议。文字演示可关闭主持人语音。 | 主持人自动开场，说明目标和三项议程，紧凑顶部显示真实倒计时。 |
| 2 | 输入：`昨天我继续核对接口联调和任务进展，今天先确认当前排期。` | 保存为成员发言，技术/排期讨论不触发纠偏。主持人开场已引用真实任务。可邀请真实成员，例如 `@李娜 你负责的 #FE-025-1 当前状态和需要的协助是什么？`；该消息使用既有数字成员能力。 |
| 3 | 连续提交：`我们周末要不要组织一次聚餐？`、`我觉得可以去学校附近吃火锅，大家有什么推荐吗？`。然后暂停输入。 | 合并发言，经语义复核后出现一条温和纠偏，明确引用当前议程。网络正常通常数秒内完成；超时降级最长约 15 秒。 |
| 4 | 点击纠偏下的“返回当前议程”。 | 显示“已返回当前议程”，保留原聊天，不阻止继续发言。可单独演示“继续讨论”或“判断有误”，同一提醒只能处理一次。 |
| 5 | 点击“下一议程”，再点一次进入“当前阻塞”。 | 主持人引导今日计划；随后结合真实 Sprint 阻塞/依赖给出 1～2 个问题。若计划期已过，会如实说明。不会同时再刷一条重复的议程播报。 |
| 6 | 输入：`我负责的 #FE-025-1 暂时做不了，因为前置的数据结构还没确定，可能影响后面的测试。` | 主持人引用真实任务，说明记录中的负责人，区分成员报告与已确认数据，追问解除条件和预计恢复时间。若不写 ID、只说模糊简称，先选择“确认阻塞任务”。刚切议程时可能等待约 8 秒的提醒间隔。 |
| 7 | 在对应追问下点击“查看依赖影响”。 | “风险与依赖”身份给出真实上游负责人、任务状态与后续关联，解释处理方向；主持人询问是否加入待确认行动。 |
| 8 | 点击“加入待确认行动”。 | 右侧出现“更新风险跟进 1 项”，展示既有风险和具体跟进措施，状态为待确认。此时项目风险与任务数据仍未修改。 |
| 9 | 右侧核对措施和依据 → 采纳 → 重新校验最终计划 → 确认应用。 | 状态变为已执行，既有风险的缓解措施更新，聊天显示实际变更；生成关联 Proposal/Action 的 ChangeHistory。无需创建新风险或伪造解除阻塞。数据若已变化则停止执行，要求重新核对。 |
| 10 | 可关闭会议室、刷新页面，再打开“查看最近会议”→“继续会议”。 | 主持提醒、反馈、计时和已执行建议恢复，不补发历史纠偏。 |
| 11 | 完成议程 → 结束会议 → 确认结束会议。 | 原会议纪要保留讨论和真实行动结果，保存实际时长。仍有待处理行动时使用“保留待处理并结束会议”，不会自动批准。 |

计时片段：另建每日站会，勾选“演示模式 · 计时 ×30”，开始后静候约 26 秒进入黄色“剩余 02:00”附近，约 30 秒进入红色“超时 +…”；聊天区各出现一次主持提醒。“更多会议操作”→延长 5 分钟或 10 分钟后总预算和倒计时重算；最后结束并展示真实时长与演示时长分开记录。扩展后的时限会有自己独立的一次提醒。

## 验证与边界

验收在 `output/scrum-phase2/data` 的真实项目副本、独立端口 18444 上进行。未向正式项目写入演示风险/任务，未提交或推送。

已用真实 Chromium UI 走通：开场 → 正常发言 → 两条闲聊 → 真实模型语义复核 → 返回议程 → 实际 Sprint 阻塞 → 任务追问 → 原风险 Agent → Proposal → 采纳/最终复核/应用 → 审计 → 刷新恢复 → 结束与原纪要。链路更新的是既有 `risk-fe025` 的跟进措施，没有新增风险。第一轮测量顶部高度为：1440px 宽约 108.5px，1024px 与 768px 宽约 135px；移动端允许换行，输入框可见。截图位于 `output/playwright/scrum-phase2-*.png`。

单元与交互测试涵盖语义证据校验、保守离线降级、误判反馈、冷却与去重、在途取消、任务确认、跨会议/事件 Proposal 去重、审批前不写回及过时事实阻止执行。本轮最终运行：39 个测试文件、464/464 测试通过；TypeScript 类型检查通过；生产构建通过（保留现有大包及无效动态导入提示）。额外以真实浏览器验证了四类会议、黄色/红色提醒、两种延期、数字成员回复、历史记录与刷新恢复。窄屏修复后“结束会议”文字保持可见。

自动化与文字浏览器验收不能证明真实麦克风识别质量、设备回声控制、中文音色或实际外放效果。本轮保留原转写与播报并执行其回归测试，设备验收留待统一试听。

本轮纠偏借鉴此前讨论的“主动会议干预”思路：上下文判断、温和提醒和可推翻反馈；会议类型化借鉴“敏捷会议 AI 助手”的流程配置思路。这是工程设计借鉴，不声称复现了任何论文实验结果，也没有新增论文知识库。
