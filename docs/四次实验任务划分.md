# ScrumFlow 项目四次实验任务划分

本清单按当前项目内容划分实验归属，以一个功能模块或一项主要过程工作为一个任务，不再展开内部实现细节。每次实验先列重点任务，再列其他任务。

| 实验 | 主要内容 | 任务数 |
| --- | --- | ---: |
| 实验一 | 项目规划、需求分析与实施准备 | 10 |
| 实验二 | 项目数据基底与传统项目管理工具开发 | 12 |
| 实验三 | 会议与 Agent 相关功能开发 | 10 |
| 实验四 | 会议扩展、优化补全、综合测试、评估与交付 | 15 |

## 实验一：项目规划、需求分析与实施准备

### 重点任务

1. **确定项目目标与范围**：明确项目背景、目标用户、核心问题和预期成果，划定必须完成的内容与暂不开展的工作。
2. **完成需求分析与用户故事梳理**：整理业务流程、目标、Epic 和 Story，明确需求优先级、业务价值与主要使用场景。
3. **制定工作分解与工期计划**：分解主要开发任务，估算工作量，确定阶段安排、依赖关系、时间缓冲和交付里程碑。
4. **确定负责人及团队分工**：敲定各实验和模块负责人，结合成员能力与可用时间安排开发、测试、评审和交接责任。
5. **制定验收标准与质量要求**：明确用户故事验收条件、阶段完成标准、成果提交要求以及最终交付门槛。
6. **确定系统架构与技术方案**：规划统一数据模型、页面结构、本地持久化方案，以及传统工具与 Agent 的接口和职责边界。

### 其他任务

7. **制作项目规划故事地图与甘特图**：使用本项目的工具呈现实际开发范围和排期，形成可供后续执行对照的计划基线。
8. **制定风险与变更管理方案**：识别工期、分工、数据、模型成本和模块集成风险，约定应对措施与需求变更确认方式。
9. **制定协作、测试与阶段评审安排**：约定代码协作规范、测试策略、评审节点及各阶段需要保留的过程证据。
10. **整理规划文档并完成阶段交接**：汇总项目章程、需求说明、分工和实施计划，评审确认后交给实验二。

**阶段产出**：项目规划与需求文档、分工表、工期与里程碑计划、验收标准、规划故事地图和甘特图。

## 实验二：项目数据基底与传统项目管理工具开发

### 重点任务

1. **建立项目数据基底与基础管理功能**：搭建统一状态和业务模型，实现项目资料、成员角色与容量、空白项目、本地保存及数据导入导出。
2. **实现用户故事地图与 Product Backlog**：按目标 → Epic → Story → Task → Subtask 组织需求，支持编辑、排序、拖拽、筛选和需求成熟度管理。
3. **实现甘特图功能**：支持分层排期、日期调整、依赖关系、关键路径、任务定位及图表导出，并与其他业务视图同步。
4. **实现 Sprint 管理功能**：支持迭代创建、范围与容量管理、启动、执行、关闭、未完成项结转和复盘，集成真实快照驱动的燃尽图。
5. **实现 Release 管理功能**：管理版本目标、发布日期与 Story 归属，支持跨 Sprint 交付、归属调整确认及按验收结果判断发布条件。
6. **实现执行看板与任务管理功能**：支持 Task、Subtask 的状态、进度、负责人、工时、阻塞和成果提交，并保持跨页面数据一致。
7. **实现成果验收功能**：支持验收标准维护、成果核对、PO 验收通过、退回返工和验收记录追踪。
8. **实现 UML 与项目用例图功能**：提供普通 UML 编辑能力，以及与故事地图顶层目标一一对应、同步修改的项目专属用例图。

### 其他任务

9. **实现设计资产管理功能**：支持文件上传、预览、下载、关联与成果复用，衔接 Story、Task、Sprint 和设计图表。
10. **实现风险管理功能**：支持风险登记、关联对象、责任人、影响、应对措施和解决状态管理。
11. **实现团队与 Sprint 分析功能**：展示成员负载、剩余容量、工作分配热力图、异常任务、迭代对比和每日态势记录。
12. **完成传统工具测试与接口交接**：验证各模块业务规则和数据联动，整理使用说明及共享接口，为 Agent 接入提供稳定基础。

**阶段产出**：能够独立完成规划、执行、验收和交付的传统项目管理版本，以及数据结构、模块测试和接口说明。

## 实验三：会议与 Agent 相关功能开发

### 重点任务

1. **实现 AI 会议室功能**：支持项目、Story 和 Sprint 会议，保存参与人、讨论消息、会议背景和历史记录。
2. **实现项目主持与多 Agent 协调**：支持自动路由、显式选择专业助手、工作对象引用及多轮上下文管理，使讨论能够连续推进。
3. **实现专业规划与分析 Agent**：完成任务拆解、风险依赖、负载容量和计划落地能力，支持方案比较、约束校验及假设推演。
4. **实现数字成员功能**：根据成员实际任务与讨论记录模拟回应，支持查询进度、说明阻塞和讨论分工，保持身份及事实边界清晰。
5. **实现事件型 Agent 功能**：识别逾期、依赖阻塞、成员超载、范围超量、成果缺失和验收缺失，提供依据与处理建议。
6. **实现统一建议审核与执行流程**：会议和事件共用 Proposal，支持人工修改、采纳或拒绝、执行前复验、确认写回和结果追溯。
7. **实现材料整理 Agent**：根据项目与会议内容生成文档、Excel 和图表，支持预览、下载、成果归档及版本管理。

### 其他任务

8. **实现会议纪要与来源追踪**：整理议题、事实、假设、决策、行动项和执行结果，支持摘要、历史回看及原始消息溯源。
9. **完成模型服务接入与调用管理**：实现服务端配置、模型路由、用量记录、异常提示和必要降级，控制调用成本并保护密钥。
10. **完成 Agent 联调与专项测试**：验证多轮对话、业务约束、事件生命周期、人工审核和材料生成，确保与传统工具共享数据并正确联动。

**阶段产出**：会议与 Agent 协作版本、可审核执行的工作建议、会议纪要与材料成果，以及模型服务和专项测试记录。

## 实验四：会议扩展、优化补全、综合测试、评估与交付

### 重点任务

1. **完成页面合并与功能精简**：整合项目资料和用例图入口，将验收、风险放回 Sprint/Release 的业务场景，减少重复摘要与零散页面。
2. **完善全局 AI 入口与快捷聊天**：提供悬浮球、功能快捷跳转和聊天小窗，支持 Agent 选择、收起、放大及跨页面继续对话。
3. **实现会议语音转写与中文播报**：选择成员进行语音发言，显示实时字幕并将完整句子记入对应成员的会议记录；支持主持人中文播报、音色与语速设置、试听及静音，处理录音与播报互斥、权限异常、切换会议和收起小窗时的音频清理。
4. **扩展 Scrum 会议类型、议程与计时**：提供每日站会、Sprint Planning、Review 和 Retrospective 模板，关联实际 Sprint 和任务；支持主动开场、议程推进、剩余时间及超时提醒、人工延期和刷新恢复，将实际用时与 30 倍演示计时分开记录。
5. **完善主动主持与阻塞跟进行动闭环**：根据成员发言进行带依据的语义纠偏，允许返回议程、继续讨论或标记误判；结合真实任务追问阻塞、调用风险与依赖分析，将跟进措施交给既有 Proposal 审核执行流程，并保留反馈、去重和审计。
6. **新增会议成果洞察与报告导出**：在纪要中展示议程推进、成员消息、主持干预、行动审核与实际执行图表，支持原始发言、Proposal 和变更审计溯源；冻结结束快照、区分会后跟进，生成 Word、Markdown、HTML 报告及对应图表数据表，接入原材料预览、下载和打包。
7. **实现隔离的课堂智能会议演示**：提供置顶的离线会议历史、关键节点跳转、方案比较、纠偏反馈、审核执行和成果展示；复用真实执行器在独立沙盒写回，从冻结快照生成纪要、WBS、风险、依赖及甘特图等材料，明确标注预设发言和独立示例来源，保持正式项目数据隔离。
8. **完成缺陷修复与功能查漏补缺**：处理跨模块数据不一致、规则遗漏、异常流程和入口缺失，补齐已有主流程中的必要操作。
9. **更新完整演示数据与典型场景**：覆盖不同版本、迭代、任务、验收、阻塞和风险状态，提供一致、可复现且明确标注模拟性质的展示数据。
10. **完成系统综合回归与最终验收**：验证传统工具、会议、事件、人工审核、材料、持久化和恢复的完整链路，补充语音生命周期、主持事件、会议快照及演示沙盒隔离的回归；真实麦克风、中文音色和外放效果另在实际演示设备上验收，整理缺陷及复测证据。
11. **完成项目及开发过程整体评估**：对照初始计划评估目标达成、工期偏差、分工协作、质量、风险处理和 AI 使用效果，总结教训与改进方向。

### 其他任务

12. **打磨界面交互与使用体验**：优化布局、信息密度、颜色、提示、定位、导出和窄屏操作，补齐会议历史置顶、消息独立滚动和菜单关闭交互，提高日常使用的连贯性。
13. **完成旧数据兼容与版本集成检查**：核对迁移、导入导出和保存恢复，检查远端合并与功能入口，兼容旧会议和本地完整演示数据，保护已有项目和组员成果。
14. **整理交付文档与运行配置**：统一需求、架构、模块说明、环境配置、测试报告和已知限制，补齐四次实验报告及相关过程资料。
15. **准备最终演示与交付归档**：整理可复现数据、演示脚本、规划图表、成果文件和备份，核对交付代码、文档与实际功能一致。

**阶段产出**：包含会议语音交互、Scrum 主持扩展、会议成果洞察与隔离演示的最终版本，完整演示数据、会议报告与材料包、回归与验收报告、项目过程评估、四次实验报告和交付资料。

## 归属说明

- **规划、实现与验收分别归类**：实验一确定需求和计划，实验二/三实现功能并开展模块测试，实验四负责整体优化和最终回归；同一模块在不同阶段对应不同工作，不重复计算开发量。
- **传统功能与 AI 能力分开**：Release、燃尽图、UML 和人工风险管理归实验二；Agent 分析、智能生成与审核执行归实验三；全局 AI 快捷入口和聊天小窗作为体验优化归实验四。
- **新增会议扩展归实验四**：实验三保留基础 AI 会议室、多 Agent、纪要、材料和人工审核执行；本次新增的语音转写、中文播报、Scrum 模板与计时、主动纠偏与阻塞跟进、成果洞察报告和课堂沙盒演示均归实验四，不回填到实验三。音视频会议类扩展按此归属；当前代码已实现上述语音能力，尚未实现的摄像头视频通话不计为已完成成果。
- **清单不代替实际过程证据**：实验编号不等同于演示 Sprint 编号，演示成员和模拟历史不代表真实开发记录；负责人、日期、完成状态与评估结论应根据团队实际情况填写。
