# 会议 Agent 意图误判修复与回归记录

日期：2026-10-10。基于本地 `main` 的 `7a7ebbb` 修复。

## 复发原因

10 月 4 日的历史验收已经记录原句失败：

> @陈林 你现在 Sprint 2 还能再接 8h 工作吗？只回答你自己的情况，不安排其他成员，不修改。

检查合并前的 `deaa3ef:src/agents/digitalMember.ts`，原判断仍是用“你 / 把 / 帮我”等词向后寻找“修改 / 更新 / 写入”。它会匹配“不修改”里的“修改”。历史审计记录了问题，但没有完成修复；这不是队友合并时把修复覆盖了。

上轮 `7a7ebbb` 只过滤数字员工入口中的部分相邻否定词。多处入口仍独立匹配原始文本，存在三层漏洞：

1. 词面匹配不区分动作请求、禁止动作、查询记录、假设或引用；固定距离的否定过滤无法覆盖“不要对任何任务做修改”。
2. 上一轮活动助手、当前话题、显式指定计划助手以及模型返回的 `intent: execute`，可能覆盖本轮只读要求。
3. 材料生成的提前返回、旧版专业助手入口、会议约束合并没有共用同一判断。“第一个任务不要交给陈林”还可能被保存成肯定的负责人覆盖。

因此，仅给提示词补一句“不修改”，或只替换某个回答模板，不能消除这类错误。

## 实际修改

- 新增 `src/agents/meetingRequest.ts`，集中提取当前请求的肯定动作、事实话题、模拟条件和约束。处理否定范围、逗号连接的并列禁止、后置禁止、没有授权、询问、假设和引用；转折后的独立肯定请求仍保留。
- 禁止动作连同对象一并排除，避免“生成子任务不要导出 Excel”被重新拼接成生成 Excel。引用保留对象类别，支持正常的“请生成‘测试报告’”，不将引用中的命令或成员名作为授权。
- 数字员工、材料及材料追问、计划交接、新增工作、旧版专业助手共用上述结果。活动助手、旧话题和模型建议不能代替当前用户提交提案的授权。
- 约束合并区分“李娜不能参与”等有效限制与“工期不要改成五天”等禁止修改；后者不会写成新的工期。禁止分配不再写成肯定的负责人覆盖。
- 新增 `src/tests/meetingIntentSafety.test.ts`，69 项回归覆盖否定变体、混合请求、上下文继承、错误模型意图、材料提前返回、旧入口及约束污染。包含正常执行请求的正向对照。
